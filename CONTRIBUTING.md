# Contributing to SkillProof

Thanks for helping. Small fixes and new ideas are both welcome.

## Ways to contribute

- **Submit a skill** for `skills-examples/` (see below).
- **Add an eval card** for a skill, with honest results.
- **Improve a check** in `validators/`, or a tool page in `docs/`.
- **Report a bug** or suggest a feature using the issue templates.

## Submitting a skill

1. Create a folder `skills-examples/<skill-name>/` with a `SKILL.md` file.
2. The name must use lowercase letters, numbers and hyphens, and match the folder name.
3. The frontmatter needs `name` and `description`. The description should say
   what the skill does and when to use it ("Use when ...").
4. Keep the skill focused on one job.
5. Open a pull request. The validator runs automatically and must pass.

## Adding an eval card

1. Create `evals/<skill-name>.eval.json`. The format is in `schema/eval-card.md`.
2. Run the test prompts yourself, with and without the skill, and record what happened.
3. Set `evidence_type` to `manual` for results you ran. Use `example` only for sample data.
4. Never invent results. An honest "partial" or "fail" is more useful than a made-up pass.

## Pull requests

- Keep each pull request small and focused.
- Wait for the "Validate skills and evals" check to turn green.
- Pages under `docs/skills/` are generated by `tools/build_pages.py`. Do not edit them by hand.
- Do not claim that a skill works with a specific agent unless you tested it, and say how.

## Code style

- Python files use only the standard library.
- Web pages are plain HTML, CSS and JavaScript, with no build step.

By contributing, you agree your work is released under the MIT license.
